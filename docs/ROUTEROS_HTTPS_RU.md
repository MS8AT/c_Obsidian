# RouterOS: HTTPS/18444 и проверяемый вход

Обновлено 06.11.2026. Это руководство для кода **0.2.1**, а не разрешение
применять изменения к любому роутеру. [Логин/пароль RU](ACCOUNTS_RU.md) ·
[EN](ACCOUNTS_EN.md) · [中文](ACCOUNTS_ZH.md).

## Что исправлено

- Отдельный `deploy/Caddyfile.routeros` сохраняет канонический LAN Host/Origin
  приложения и добавляет отдельное публичное DNS-имя с HTTPS на указанном порту.
- Только Origin публичного сайта переводится в канонический Origin. Чужие Origin
  не удаляются и не разрешаются; API продолжает проверять авторизацию и CSRF.
- Корень без сессии перенаправляет на `/login`; публичны login.js и style.css.
  `/app.js` и `/api/graph` до входа должны возвращать **401**, а не 200.
- RouterOS state flags могут сериализоваться как null: остановка подтверждается
  `stopped=true`, запуск — `running=true`. Отсутствующий running не доказывает stop.
- Native validate вызывается non-interactive через `shell cmd=... no-sh`.
  `no-sh` не исполняет последующий RouterOS END marker: проверяют код выхода
  команды и строку `Valid configuration`, а не интерактивное приглашение.

## Настройки контейнера

В образ 0.2.1 включён `Caddyfile.routeros`. Выбирается флагом
`OBSIDIAN_ROUTEROS_GATEWAY=1`; не включайте одновременно shared gateway.
Задайте точные значения в envlist выбранного контейнера:

| Переменная | Значение |
|---|---|
| `OBSIDIAN_DOMAIN` | Канонический LAN IP/DNS с портом, например `<lan-host>:18444` |
| `OBSIDIAN_TLS_NAME` | Тот же канонический IP/DNS **без** порта, для клиентов без SNI |
| `OBSIDIAN_PUBLIC_DOMAIN` | Отдельное публичное DNS-имя с портом, `<public-domain>:18444` |
| `OBSIDIAN_SECURE` | `1` |

Замените placeholders своим проверенным адресом; две domain-переменные должны
быть различны. `/state`, `/vault`, `/data`, `/config` сохраняются в отдельных
постоянных mounts. Если `/etc/caddy` перекрыт mount, каталог должен содержать
проверенный `Caddyfile.routeros`; файл внутри image тогда скрыт этим mount.

На уже работающем контейнере проверьте кандидата из доступного mount:

```routeros
/container shell <container-name> cmd="caddy validate --config /config/Caddyfile.routeros --adapter caddyfile" no-sh
```

Имя контейнера, путь кандидата и его envlist проверяют заранее. Только после
PASS выполняют согласованный stop/config activation/start одного контейнера,
readback и проверки. Не повторять команды изменения при UNKNOWN без сверки.

## Доступ из интернета

Публикация TCP-порта требует отдельно согласованных DNS, публичного WAN IPv4,
точного WAN interface, dstnat на контейнер и узкого forward-разрешения перед
container-guard drop. Разрешение должно совпадать только с нужным контейнером,
протоколом TCP и портом 18444. Сохраните исходные правила и точный rollback;
не отключайте общий firewall и не перенаправляйте чужие 80/443.

Разрешённые внешние IP задаются оператором; открытие для всех не является
неявным default. DNS/адрес из датированного снимка не заменяет свежий readback.
`EXPOSE` в Dockerfile сам по себе не публикует порт на RouterOS.

Шаблон использует существующий **локальный CA Caddy**: шифрование и соответствие
сертификата имени проверяются, но CA должен быть доверенным на клиенте.
Windows/browser trust автоматически не меняется. Открывайте полный `https://`
адрес с DNS-именем и портом. HTTP на TLS-порту вернёт сообщение об ошибке;
`ERR_SSL_PROTOCOL_ERROR` не является обычным предупреждением о CA.

TLS, форма входа и её JS/CSS, отказ 401 без сессии, Origin=403 для чужого сайта,

`https://obsidian.ms8at.by:18444/login` открылся из текущей сети с проверкой app CA.

Это проверка установленной 0.2.0 с отдельной согласованной конфигурацией, а не
доказательство развёртывания нового образа 0.2.1. Независимый внешний клиент,
авторизованный login, persistence после restart и операторская приёмка — **NOT_RUN**.
Успешные source tests, CI, image build, runtime и acceptance учитываются отдельно.
